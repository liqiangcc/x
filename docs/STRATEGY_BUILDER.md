# 配置驱动策略编排

策略系统按以下层次组织：

```text
能力注册表 -> 指标实例 -> 规则实例 -> 组合/发射/排序机制 -> 策略模板修订 -> 策略实例修订 -> 某日信号
```

- 特征和指标只产生数值，不决定股票是否入选。
- 规则引用特征或指标并输出真假及证据。
- 模板保存一组可复用的指标和规则；系统预置模板不可修改，用户可以保存自定义模板。
- 策略实例保存模板展开后的配置快照、市场范围和排序方式。修改或删除模板不会改变已有策略。
- 当前组合只开放 AND；是否每天发出信号由 `emission.mode`（`on_match` / `on_enter`）独立控制。
- 候选排序由 `ranking` 声明，默认按当日收盘价升序，不再由候选管道写死具体策略字段。

## 默认模板

默认 V3 模板为“连续下跌3年后首次突破”：

1. `sequence_compare` 读取最近4个完整年度收盘点，要求形成3次连续下降。
2. `first_occurrence` 要求今日收盘高于去年最高价，且本年度此前没有收盘高于该价格。

因此，“连续下跌3年”需要4个年度收盘点；最早年度只是第一次下降的比较基准，并不表示连续下跌4年。

## 已注册积木

指标：

- `moving_average`：移动平均线。
- `boll`：布林线上轨、中轨和下轨。
- `rolling_extreme`：指定窗口的最高值或最低值。

规则：

- `sequence_compare`：有序序列连续比较。
- `value_compare`：两个标量直接比较。
- `cross`：两个值在相邻交易日发生上穿或下穿。
- `first_occurrence`：当前满足条件，指定历史范围内此前从未满足。

页面可以创建任意多个已注册指标实例和规则实例。每项能力同时注册参数模式、输出、计算器、依赖和说明。页面根据 `paramSchema` 生成编辑控件；通用编译器只遍历注册表生成执行计划，不识别具体指标或规则名称。新增能力不需要修改编译器、候选管道或页面主流程。

## V3 配置结构

```json
{
  "schemaVersion": 3,
  "type": "composite",
  "indicators": [],
  "rules": [],
  "composition": { "operator": "all", "ruleKeys": [] },
  "emission": { "mode": "on_match" },
  "ranking": [
    { "operand": { "kind": "feature", "id": "daily.today.close" }, "direction": "asc", "nulls": "last" }
  ]
}
```

指标、规则是基础能力；`composition`、`emission`、`ranking` 是通用编排机制。候选证据统一包含规则结果和排序值，避免上层依赖某个策略的专用 evidence 字段。

## 修订与迁移

- 模板每次保存追加不可变修订，模板头只指向 `current_revision`；策略保存模板 ID 和修订号作为来源信息，同时保存展开后的完整快照。
- 策略每次修改追加修订。已有可用策略采用影子构建，新修订成功后才切换 `active_revision`；失败时旧修订继续服务。
- 启动时对可用 V2 策略串行使用同一份当前数据构建 V2 基线和 V3 影子修订，再比较全部“交易日 + 股票代码”信号身份。完全一致才切换；不能拿可能基于旧行情生成的历史索引直接比较。失败时记录原因并保留 V2。
- V2 编译器保留一轮只读兼容，页面和新建模板只写 V3。

## 涨跌停能力设计

涨停不是一个专用策略，而是一组由行情和证券规则派生的标准特征。分层保持为：

```text
日线 OHLC/涨跌幅 + 证券代码 + 模拟日期
  -> 历史涨跌停规则解析器
  -> 当日涨停状态特征
  -> 通用布尔/次数规则
  -> 首板、连板、炸板等策略模板
```

第一阶段注册以下布尔特征：

- `daily.today.is_limit_up`：收盘达到涨停状态。
- `daily.today.touched_limit_up`：最高价曾达到涨停状态。
- `daily.today.opened_limit_up`：开盘达到涨停状态。
- `daily.today.broken_limit_up`：盘中触及但收盘未封住涨停。
- `daily.today.is_one_price_limit_up`：开、高、低、收均处于涨停价附近。

新增通用规则：

- `boolean_feature`：指定布尔特征等于真或假；属于事件规则，可以单独形成候选信号。
- `window_count`：指定布尔特征在最近 N 个交易日出现至少/至多/恰好多少次；属于状态规则，应与事件规则组合。
- `consecutive_count`：指定布尔特征截至今日连续出现至少多少个交易日；属于事件规则。

例如“最近20日首次涨停”可以组合为“今日收盘涨停”与“最近20日涨停次数恰好1次”；“二连板”可以使用“收盘涨停连续至少2日”。这些规则不包含股票筛选、排序或模板名称，因此也能复用于跌停、大阳线、放量等后续特征。

### 历史口径与质量边界

涨停判断优先使用日线源数据携带的当日涨跌幅，缺失时才使用前收盘和当日 OHLC 推导。规则解析器按模拟日期和代码所属板块确定普通 A 股基准比例，并统一处理价格精度容差；策略层不能自行写死比例。

当前账本缺少完整的历史证券状态、上市阶段和不复权行情，因此第一阶段明确采用 `legacy_approximate` 口径：

- 默认候选范围继续排除可识别的 ST、退市整理证券。
- 无法可靠识别历史 ST、上市初期无涨跌幅限制等特殊状态时，结果附带质量标记，不伪装成精确结果。
- 盘中“触及”和“一字板”属于日线级近似，不能推断封单、开板时间和盘中持续时长。
- 后续接入有效期证券状态和不复权行情后，仅替换涨跌停规则解析器，不修改规则、模板和策略实例结构。

### 验收标准

1. 默认旧策略不引用涨停特征时，计算结果和性能不发生语义变化。
2. 页面可以直接添加涨停布尔、窗口次数和连续次数规则，无需编辑 JSON。
3. 服务端拒绝未知特征、非法窗口和无效组合引用。
4. 全量索引只读取模拟日及以前的数据，不读取未来日线。
5. 候选证据包含命中的涨停特征、适用比例、计算来源和数据质量标记。

## 接口

- `GET /api/strategy-builder/catalog`：基础特征、指标、规则及参数限制。
- `GET /api/strategy-templates`：预置模板和用户自定义模板。
- `GET /api/strategy-templates/:templateId/revisions`：模板的不可变修订。
- `GET /api/strategies/:strategyId/revisions`：策略构建和迁移修订。
- `POST /api/strategy-templates`：保存自定义模板。
- `PUT/DELETE /api/strategy-templates/:templateId`：修改或删除自定义模板。
- `POST /api/strategies/validate`：服务端编译并校验策略草稿。
- `POST /api/strategies`：保存策略实例并开始构建全量索引。

策略同步首先执行编译器生成的年线预筛计划，只同步预筛代码的日线，然后聚合年线并重建完整索引。没有年线预筛规则时，同步范围会退化为所选板块的全部代码。
